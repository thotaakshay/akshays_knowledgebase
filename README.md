## Update policy
1. Read the relevant current KB before changing it.
2. Do not store every conversation detail.
3. Distinguish established knowledge, observed evidence, working hypotheses, verified rules, personal rules, and open questions.
4. Replace or correct superseded current rules instead of leaving contradictory guidance active.
5. Preserve useful failure evidence when it explains why a rule changed.
6. Use descriptive Git commits so any change can be inspected or reverted.
7. Do not silently promote one scene-specific result into a universal rule.

Git history is the rollback layer. Important KB changes should be committed separately when practical.
